# Mentor Bot

Telegram Business бот-ассистент ментора: авто-пинги менти каждые 3 дня тишины,
ведение Google-таблицы, черновики ответов по базе знаний курса.

## Установка

1. **Бот**: у @BotFather → `/newbot`, токен в `.env` (`BOT_TOKEN`).
2. **Telegram Business** (нужен Premium): Настройки → Telegram для бизнеса → Чат-боты →
   добавить бота, разрешить читать и отправлять сообщения.
3. **Свой ID**: у @userinfobot, в `.env` (`MENTOR_USER_ID`).
4. **Google**: console.cloud.google.com → проект → включить Google Sheets API →
   Credentials → Service Account → ключ JSON → сохранить как `service_account.json`
   рядом с docker-compose. Таблицу расшарить (Viewer недостаточно — Editor) на
   email сервисного аккаунта (`...@...iam.gserviceaccount.com`).
5. **LLM**: ключ OpenRouter в `.env` (`LLM_API_KEY`). Модели — в нотации OpenRouter (`openai/gpt-5.6-sol`); другой OpenAI-совместимый провайдер подключается через `LLM_BASE_URL`.
6. **Edu-платформа**: логин/пароль в `.env` (`EDU_EMAIL`, `EDU_PASSWORD`) — нужны краулеру
   для авторизации на edu-платформе при `/reindex`; без них база знаний не соберётся.
7. `cp .env.example .env` и заполнить. `ACTIVE_SHEETS` — точные названия листов через запятую.
8. `docker compose up -d --build`

## Первый запуск

- После обновления запусти `/reindex`: база знаний пересобирается с источниками уроков
  (старый индекс работает, но без ссылок на уроки).
- Бот стартует в **dry-run**: все пинги и черновики приходят тебе, ученикам ничего не уходит.
- Напиши боту `/start`, затем `/reindex` (соберёт базу знаний с edu-платформы).
- `/status` — сводка. Чаты привязываются по мере переписки; «не привязан» лечится
  одним сообщением в чат с учеником.
- Когда тексты устраивают: `/dryrun off`.
- Бот сам добавит в лист колонку **«Досье»** и будет заполнять её раз в сутки. Колонку
  **«Заметочки»** он только читает — твои пометки там в безопасности и влияют на тексты пингов.
- Ответы ученика не уходят в модель сразу: бот ждёт 5 минут тишины (`DEBOUNCE_MINUTES`) и
  разбирает всё накопленное одним запросом. Если ты ответил сам за это время — черновик
  не создаётся.
- Статус в таблице бот НИКОГДА не меняет сам: и по словам ученика, и по твоему
  «сдан спринт 1» он присылает кнопки «Да / Нет».
- Темы пинга ограничены стадией ученика. Конвейер:
  `Спринт 1 → 2 → 3 → 4 → Резюме → Легенда → Мок → Рынок → Собесы → оффер`.
  Все четыре спринта — учёба: про резюме, легенду, HR, собесы и рынок бот там молчит.
  На стадии «Резюме» мяч у тебя — бот пингует ученика и отдельно напоминает тебе,
  сколько дней тот ждёт резюме.

- Бот пишет в таблицу только после сверки: перед записью он заново находит строку ученика
  по `@username`, так что сортировка листа и вставка строк не приводят к записи в чужую строку.
  Кнопка смены статуса проверяет, что в таблице всё ещё тот статус, от которого считалось
  предложение, — старая кнопка не откатит статус назад.
- Любая смена статуса (кнопкой или руками в таблице) пишется в историю; от неё считаются
  «ждёт резюме N дн.» и аналитика в `/digest`.

## Черновики ответов

- Под черновиком три кнопки: «Отправить», «✏️ Править», «Игнор». После «Править» просто
  пришли боту свой текст — он уйдёт ученику вместо черновика (`/cancel` — передумал).
- Бот запоминает, что в итоге ушло ученику: черновик, твою правку или твой ответ в чате.
  В следующих черновиках учитываются твои правки (тон, длина) и твои ответы на похожие
  вопросы. В конце черновика — ссылка на урок, откуда взят ответ.

## Пинги

- Запрещённые для стадии темы проверяются не только промптом, но и кодом. Нарушил — пинг
  переписывается; нарушил повторно — приходит тебе на одобрение, ученику не уходит.
- `/pingmode review` — все пинги сначала приходят тебе с кнопками «Отправить / Править /
  Пропустить». Если ученик написал сам, пока пинг ждал, отправить его бот откажется.

## Аналитика

- `/digest` (и автоматически по понедельникам в 10:00): воронка по стадиям, кто сдвинулся за
  неделю, кто застрял, кто не отвечает на пинги, медиана времени на каждой стадии.
  Время считается по Каплану–Мейеру: тех, кто ещё на стадии, не выбрасывают, иначе
  оценка занижена. Нужна история — цифры появятся после нескольких переходов по стадии.
- На стадиях «Рынок» и «Собесы» бот вытаскивает из рассказов ученика вопросы с собесов.
  `/fails` — темы, на которых срезались, по числу разных учеников.
- `/cost [дней]` — токены и деньги на LLM по типам задач.
- Каждую ночь бот присылает бэкап базы (`.db.gz`) тебе в личку; `/backup` — сейчас.
  В бэкапе вся переписка с учениками — не пересылай его никуда.

## Качество поиска по базе знаний

Собери `cases.jsonl` — по строке на реальный вопрос:
`{"question": "как закрыть канал", "expected": "Каналы"}` (`expected` — кусок названия урока
или текста нужного фрагмента) — и запусти `python -m mentor_bot.eval_kb cases.jsonl 5`.
Выведет recall@5 и вопросы-промахи. Меняешь поиск — сравниваешь цифру до и после.

## Команды

/status, /digest, /fails, /cost [дней], /pause @user N, /pause_all, /resume_all,
/dryrun on|off, /pingmode auto|review, /cancel, /backup, /reindex
